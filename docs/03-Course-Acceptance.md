# 课程验收与证据清单

第一优先级：老师要求实际设计与实现 horizontally scalable cloud-native microservice-oriented system。保留项目题材，不保留原单 Worker 部署作为最终架构。

## 四项完成前不扩展可选功能

1. 独立客服应用 + 至少十条固定用例 + 真实模型结果 + 两个 prompt 比较。
2. 云端实际运行独立服务 + 执行器水平扩展 + 自动扩容记录 + 同一负载的对照实验。
3. 托管 CI 的真实运行链接 + 镜像摘要 + 批准后部署 + smoke + 失败阻断。
4. 多身份 UAT + 权限/租户隔离 + 独立审核 + 持久化 + 故障恢复证据。

## A 需求 前端与 UAT

- 写出 UC1–UC7 的验收步骤、预期与实际、测试账号、证据路径。
- UI 完整表达 queued/running/finished 和 gate passed/blocked；finished 不等于通过，通过不等于批准。
- 审核人在固定业务 rubric 上给出理由；切换实际云端用户身份，而不是仅改 UI 名字。
- 记录团队实际里程碑和成员投入，组织 40 分钟含问答的演示。

## B 服务与数据

- 讲清三个业务边界、API、数据归属和 worker 所属上下文。
- 验证 job/outbox 原子写、重复 key 重放/冲突、租户隔离、旧快照不变、竞争审核仅一次。
- 解释异步最终状态、故障重试、租约及重复 provider 请求风险。
- 每个服务独立部署/重启；不跨库查询。保存 schema/API 变更与 review。

## C 独立应用与模型

- 使用实际授权 provider，固定 model ID、policy、case IDs、prompt 内容和版本。
- 两个 prompt 使用同一个 suite ID；保留逐项原始输出、错误、耗时和运行时间。
- `human-rubric.csv` 记录独立人工判定及理由，不能从规则分数自动产生。
- 规则/真实结果/回放容量样本明确区分。没有模型账号时记录阻塞，不制造真实结果。
- 证明 CLI 非零状态阻止消费方下一步骤；业务审批记录不自动部署应用。

## D 云端与 DevSecOps

- 先选云平台、账户及预算；配置 HTTPS、OIDC claim 合同、镜像仓库、DB/broker secrets。
- 保存 clean install、类型/领域/API 检查和漏洞扫描的真实 hosted run 链接。
- 从 exact commit 构建镜像；部署已测试的相同 digest，保留人工批准、rollout 和 smoke。
- 配置队列驱动自动扩容；保留副本/队列随时间变化。集群节点不足也必须记录。
- 回滚应用版本并复验；数据库恢复与应用回滚分别描述。不能宣称前者已完成。

## E 独立验证与性能

- 先验证平台行为，再压测；记录 endpoint API 延迟和异步 job 完成延迟，二者分开。
- 同一数据集/负载/每实例规格，对照 1/3/5 执行器，固定时间或任务数；重复实验，记录离散程度。
- 云端覆盖 100/1,000 个十用例任务、读/写 workload、队列积压、吞吐、p95、错误、数据库增长；若课程/老师另有最新要求，以其为准。
- 自动扩容实验使用持续到足以触发 scaler 的任务流；记录采样间隔、阈值、扩容/缩容延迟和最大实例数。
- 停止一个执行器后验证任务恢复、attempt 增加和只有一个最终结果；重复提交及并发审核不产生重复最终记录。
- 本地回放结果只能支持本地回放结论；没有收益时分析 API/数据库/broker/共享 CPU，不能加入无业务意义的计算或等待来做出“好看”的数字。

## 报告章节与必备证据

- Introduction：具体业务、seed/producers/consumers、范围与未实现范围。
- Project Conduct：50 人天估算、真实 WBS/日期/小时、问题与实际项目状态。
- Logical Architecture：边界、协议、静态/动态视图、关键决策及备选取舍。
- Physical Architecture：云节点/网络/资源/服务、身份和秘密、数据库所有权、代表性流程。
- Quality Attributes：需求场景 → 实现策略 → 测试输入 → 实际指标 → 限制。
- DevOps：仓库/分支/review、托管 CI/CD、批准与回滚、失败阻断。
- Architecture Limitations：云依赖、单点、provider 配额、至少一次处理、未验证恢复与成本风险。
